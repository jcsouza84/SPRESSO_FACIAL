Filtros de Qualidade

Controlam quais rostos são processados, reconhecidos e disparam alertas. Valores mais altos = menos falsos positivos, mas também menos detecções.

0.65
Score interno do modelo Hailo para aceitar uma detecção como rosto. Valores baixos (0.40) capturam mais rostos mas também mais falsos positivos (carros, objetos). Recomendado: 0.60–0.70.

Tamanho mínimo do rosto (em pixels) para cada etapa do pipeline:

Rostos menores que este valor em pixels são ignorados completamente — não geram evento nem alerta. Equivale a distância mínima da câmera. Recomendado: 60–100 px.
Abaixo deste tamanho o rosto é registrado mas não comparado com o banco de pessoas cadastradas — reduz comparações imprecisas de rostos pequenos/distantes. Recomendado: 100–150 px.
Mesmo que reconhecido, o alerta via WhatsApp só é enviado se o rosto for maior que este valor. Garante que a pessoa está próxima o suficiente para uma identificação confiável. Recomendado: 130–200 px.
50%
Percentual de confiança do reconhecimento facial para enviar alerta. 50% = metade da confiança máxima. Aumentar reduz alertas errados mas pode perder identificações. Recomendado: 50–65%.

Filtro de Ângulo Facial

Quando ativo, rostos muito laterais ou de perfil são ignorados no reconhecimento. Elimina a maior fonte de falsos positivos em câmeras externas.
40°
Ângulo máximo de desvio horizontal do rosto (yaw). 0°=completamente frontal, 90°=perfil puro. Valores menores são mais restritivos. Recomendado: 30°–45°.

Verificação de Presença Humana

Usa o modelo YOLOv5s PersonFace no Hailo para confirmar que existe uma pessoa no frame antes de processar rostos. Elimina alertas de fotos, TVs e objetos. Adiciona ~10ms de latência por frame.

Threshold de Reconhecimento

Distância máxima entre embeddings para considerar a pessoa reconhecida. Menor = mais restritivo (menos falsos positivos). Recomendado: 0.40–0.55
